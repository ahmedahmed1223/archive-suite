# تصميم تخزين تمثيلات الحفظ للإصدار 2

**الحالة:** مسودة محدثة للمراجعة قبل خطة التنفيذ

## الهدف

يضيف النظام تمثيلات فيديو فعلية ومثبتة على إصدار المصدر: نسخة حفظ مستقلة ونسخة
Mezzanine موحدة للتحرير ونسخ مدارة إلى مخازن خارجية. لا تظهر أي نسخة جاهزة قبل
نجاح الكتابة والتحقق، ولا يعدّ النظام النسخ المحلي أو Drive ضمانًا متعدد المواقع.

## سياسة السيادة التخزينية

لكل بيئة سياسة إدارية صريحة:

| السياسة | مصدر الحقيقة | دور الجانب الآخر |
| --- | --- | --- |
| `local_primary` | قرص محلي مستقل للحفظ | وجهات خارجية للنسخ الاحتياطي المتحقق |
| `external_primary` | مزود خارجي محدد | مساحة محلية للإدخال والذاكرة التشغيلية والتحويل |

لا يغير النظام السياسة أو ينقل موادًا قائمة تلقائيًا. أي انتقال ينشئ خطة ترحيل
مدققة قابلة للمراجعة، وتبقى السياسة القديمة فعالة حتى اعتماد الخطة.

## الأقراص والموصلات

- يضاف قرص Laravel باسم `preservation` منفصل عن وسيط الإدخال في Docker.
- التخزين المحلي هو الافتراضي، وتوفر الموصلات وجهات أو مصادر لـ Dropbox وGoogle
  Drive وS3 وAzure Blob وأي مزود Flysystem لاحق.
- لا يكشف API أو الواجهة مسارات التخزين أو مفاتيحه أو رموز OAuth أو سلاسل الاتصال.
- يثبت كل تمثيل على `MediaDerivative` و`version_token`؛ فالنتيجة ذات بصمة قديمة
  تخفى ولا تصبح قابلة للبث.
- لا يستعمل العرض الخارجي إلا `review_proxy` المحروق علامته المائية.

## نموذج النسخ المادية

`MediaDerivative` يصف التمثيل المنطقي وإصدار مصدره، أما سجل `MediaReplica`
المنفصل فيصف وجوده المادي في وجهة واحدة. يحمل السجل: `representation_id`،
الوجهة، معرف الكائن ونسخته لدى المزود، حالة النقل، الحجم، SHA-256، رقم المحاولة،
وقت آخر تحقق، ورسالة خطأ منقحة. لذلك يمكن لتمثيل واحد أن يملك نسخة محلية ونسخة
Dropbox ونسخة S3 من دون خلطها أو الادعاء بأن أحدها بديل عن الأخرى.

الحالات الموحدة هي `queued` و`transferring` و`verifying` و`ready` و`failed`
و`missing` و`restore_pending`. تصبح النسخة `ready` فقط بعد قراءة لاحقة تطابق
الحجم والبصمة، ولا تستعمل حالة الوجهة أو رد HTTP وحدهما دليلًا كافيًا.

## قدرات الموصلات

لا يعدّ أي موصل داعمًا لمجرد كونه Flysystem. يسجل كتالوج موصلات منفصل قدراته
الفعلية: استيراد، رفع متعدد الأجزاء أو قابل للاستئناف، قراءة نطاقية، استرجاع
الإصدار، حذف منطقي أو نهائي، عرض السعة، والتحقق بالقراءة. لا تظهر عملية في
الواجهة إلا حين يعلن الموصل قدرتها، وتظهر بوضوح وظيفة غير متاحة بدل نجاح وهمي.

تدعم Dropbox وGoogle Drive الاستيراد والرفع والتحقق حين تمنح الصلاحيات المناسبة؛
ولا تفترض المنظومة أن لهما قراءة نطاقية أو إصدارات أو حذفًا غير قابل للاستعادة
بالطريقة نفسها التي يوفرها مخزن كائنات. S3 وAzure Blob هما المزوّدان المرجعيان
للتخزين الخارجي الأساسي عندما تتطلب السياسة رفعًا متقطعًا واستعادة دقيقة.

## التخزين الخارجي الأساسي والتشغيل المحلي

عند `external_primary` لا يقرأ العامل ملفًا بعيدًا في مكانه. ينشئ مهمة تجهيز
تنزل الإصدار المحدد إلى مساحة مرحلية محلية مشفرة ومحدودة الحجم، تتحقق من البصمة،
وتمنح العامل مسارًا قصير العمر لـ `ffprobe` و`ffmpeg`. تسجل السعة المحجوزة، وتنظف
المساحة عند النجاح أو الفشل، وتبقيها فقط ضمن فترة تشخيص مضبوطة. يرفض النظام بدء
تحويل جديد إن لم تكف المساحة أو لم يمكن التحقق من المصدر الخارجي.

## سجل النسخ وعمليات الموصل

تسجل كل نسخة مادية: نوع التمثيل، الوجهة، معرّف المزود، حالة النقل، الحجم،
SHA-256، وقت آخر تحقق، وخطأ منقح عند الفشل. لا يكفي رد الرفع لاعتبار النسخة
جاهزة؛ يقرأ الموصل أو يفحص الملف لاحقًا ويطابق الحجم والبصمة قبل `ready`.

العمليات الموحدة هي: استيراد، رفع، نسخ احتياطي، تحقق، مقارنة، استعادة، إعادة
محاولة، وحذف محكوم بالصلاحيات. حذف نسخة خارجية عملية منفصلة مدققة ولا يحذف
المصدر المعتمد أو النسخة المحلية تلقائيًا. عند غياب النسخة الأساسية لا يسلم
النظام النسخة الاحتياطية بصمت؛ ينشئ استعادة صريحة إلى الوجهة المعتمدة.

## الاحتفاظ والحذف والاستعادة

تحدد السياسة حد احتفاظ لكل نوع تمثيل، وتعليقًا قانونيًا اختياريًا، وفترة حذف
منطقي قابلة للاستعادة. لا يسمح بالحذف النهائي إن كانت النسخة آخر نسخة `ready`
لتمثيل معتمد، أو كانت المادة تحت تعليق قانوني. يتطلب الحذف النهائي موافقة
مزدوجة وسجل تدقيق يثبت المبرر والموافقين والوجهات المتأثرة.

الاستعادة عملية مستقلة تحدد المصدر والوجهة والإصدار المتوقع والبصمة. عند تعارض
إصدار المزود أو تغيره أو اختفائه، تتوقف العملية بحالة واضحة ولا تستبدل أي نسخة
موجودة. لا تنتقل المادة تلقائيًا بين مزودين خارجيين؛ هذه عملية ترحيل منفصلة.

## الاعتمادية والسعة

تحدد الإدارة RPO لكل وجهة وفترة تحقق دورية وحد سعة تحذيري وحدًا حرجًا. تسجل كل
نسخة آخر نجاح وآخر تحقق وتأخرها عن RPO. تفتح المنظومة تنبيهًا ومهمة تدارك عند
تجاوز RPO أو فشل التحقق أو انخفاض السعة أو نفاد المساحة المرحلية. يقاس RTO عبر
تمرين استعادة مدقق على نسخة معزولة، ولا يعرض رقم RTO قبل وجود دليل هذا التمرين.

## تدفق المعالجة

1. بعد إدخال فيديو مقبول، تدرج مهام `preservation_copy` و`mezzanine` ومهام
   النسخ التي تفرضها السياسة.
2. يكتب العامل نسخة الحفظ في الوجهة الأساسية ويؤكد الحجم وSHA-256؛ وينشئ
   Mezzanine بصيغة FFV1/MKV ويؤكد قابليتها للقراءة عبر `ffprobe`.
3. ينسخ عامل النسخ الاحتياطي التمثيل المتحقق إلى كل وجهة مفعلة ثم يتحقق منها.
4. يفهرس `GET /media-representations` المصدر والتمثيلات الحالية فقط، ويعرض
   `processing` و`failed` و`missing` بلا مفاتيح أو مسارات.
5. يعرض السجل والاستوديو الاسم والحالة وبصمة الإصدار والسيادة؛ وتعرض الإدارة
   الموصلات والسعات والأخطاء وخطط الترحيل من دون أسرار.

## واجهات الإدارة والتشغيل

- **سياسة التخزين:** اختيار `local_primary` أو `external_primary`، الوجهة
  الأساسية، RPO، الاحتفاظ، والحدود؛ التغيير ينشئ معاينة وخطة ترحيل ولا ينفذ فورًا.
- **الموصلات:** ربط حساب أو إعداد مزود، اختبار الصلاحية، عرض القدرات، إلغاء الربط،
  وحالة صحة الاتصال. تحفظ الأسرار في إعدادات الخادم ولا تعود إلى المتصفح.
- **تفاصيل المادة والاستوديو:** قائمة النسخ المادية مع السيادة والحالة والبصمة
  ووقت التحقق، وإجراءات إعادة المحاولة أو الاستعادة المتاحة بحسب الصلاحية.
- **مركز عمليات التخزين:** طوابير النقل والتنبيهات والسعة وتأخر RPO وخطط الترحيل،
  مع فلاتر للوجهة والنوع والحالة.
- **حوار الحذف:** يشرح أثر الحذف والاحتفاظ والتعليق القانوني، ويجمع المبرر
  والموافقة الثانية قبل التنفيذ النهائي.

## النزاهة والاختبار

- فشل النسخ أو البصمة أو `ffmpeg` يسجل سببًا منقحًا؛ وإعادة المحاولة مستقلة
  ومدققة.
- لا تحذف النسخ السابقة تلقائيًا عند تغير المصدر، بل تخفى وتمنع من الاستخدام
  كتمثيلات للإصدار الحالي.
- تغطي الاختبارات السياسة المحلية والخارجية، فشل التحقق، الاستعادة الصريحة،
  ومنع حذف النسخة الأساسية بلا صلاحية.
- تختبر اختبارات الموصلات مصفوفة القدرات وتعارضات إصدار المزود والرفع المستأنف
  والتنظيف المرحلي وحدود السعة، باستخدام مزودات مزيفة لا حسابات خارجية حقيقية.
- يثبت اختبار حي عند 1280 و375 ظهور التمثيلات وسيادة التخزين وحالة الموصلات
  دون أسرار، ثم تمر العقود وLaravel وNext.js وDocker.

## خارج النطاق

- LTO وBagIt/PREMIS والنسخ التلقائي بين مزودين خارجيين.
- اعتبار Dropbox أو Google Drive وحدهما حفظًا طويل الأجل متعدد المناطق.
- إتاحة نسخة الحفظ أو Mezzanine برابط عام أو بديلًا عن `review_proxy`.
