## 1. المرجع البصري المختار

من بحث DesignMD عن «dark media archive dashboard / warm gold premium»، الأقرب لهوية Arch_App الحالية («Cinematic Dark» + ذهبي `#E8B447`):

| المرجع | ما نأخذه | ما نرفضه |
|---|---|---|
| **Linear** (الأقرب للمنتج) | سلّم أسطح رباعي بدون ظلال، حدود شعرية 1px، لون تمييز واحد نادر الاستخدام، نص ثانوي رمادي بارد متدرّج 4 درجات | اللون البنفسجي — نبقى على الذهبي |
| **Runway** | الطابع السينمائي: الواجهة تتراجع والمحتوى الإعلامي هو البطل؛ صفر ظلال؛ عناوين مضغوطة line-height ≈1.1 | الصور الكاملة full-bleed في صفحات البيانات |
| **Superhuman** | الدفء الهادئ: نص أساسي غير أسود صرف، وزن وسيط 500–600 للنصوص الصغيرة، فعل أساسي واحد لكل شريط | ثلاثية اللوحات الملونة |

**قرار مسجل (DesignMD `record_design_decision`):** زر التمييز يبقى مستطيلًا بزوايا `--radius-lg` الحالية، أبدًا pill؛ لون تمييز واحد فقط (الذهبي)؛ الظلال تُستخدم للطبقات العائمة فقط وليست للبطاقات.

## 2. الأنماط المعتمدة من DesignMD ومقابلها في الكود

### 2.1 حالات الفراغ — نمط `empty-state`
المصدر: `get_pattern("empty-state")`. المكوّن موجود: `components/EmptyState.tsx` + `.empty-state` في `04-tables.css`.

الفجوات مقابل النمط (تُصلح موجة 2 — V14-UX-003/004):
1. **ثلاث حالات فراغ مختلفة يجب فصلها** — الأولى (لا بيانات بعد): CTA إنشاء قوي («ارفع أول ملف»). الفلترة الفارغة: CTA «امسح الفلاتر» وليس CTA إنشاء. ممنوع الوصول: شرح + طلب صلاحية. حاليًا الرسالة واحدة.
2. **التوسيط العمودي داخل الحاوية** وليس الصفحة: `.empty-state-rich` شبكة بلا توسيط — إضافة `place-content: center; min-block-size: 12rem` للحاوية الكاملة.
3. الأبعاد: أيقونة ≤80px داخل بطاقة، عنوان سطر واحد، وصف ≤سطرين بعرض أقصى 320px، CTA بارتفاع 36–40px غير full-width.
4. الانتقال هيكل→فراغ يتم بعد اكتمال الجلب فقط (لا فراغ قبل الجواب).

### 2.2 حالة الخطأ — نمط `error-state`
المصدر: `get_pattern("error-state")`. يعالج ملاحظة DESIGN_REVIEW رقم 5 (انهيار صامت).

1. `AsyncStateSurface` موجود لكنه مستخدم في **صفحة واحدة فقط** من 65 — التعميم هو V14-UX-004 نفسها؛ النمط يؤكد المواصفة:
   - `role="alert"` عند الخطأ (موجود ✓)، زر «إعادة المحاولة» يعيد نفس العملية دون reload كامل.
   - لا نص خطأ خام من الخادم أبدًا؛ رسالة هادئة + خطوة تالية.
   - خلفية حمراء كاملة ممنوعة — أيقونة دلالية فقط.
   - عند خطأ الشبكة: محاولة صامتة واحدة ثم إظهار الحالة.
2. لافتة «الخادم غير متاح» تعتمد `api.health()` الموجود وغير المستخدم (P0 سابق لم يُغلَق).

### 2.3 لوحة الفلاتر — نمط `filter-panel`
المصدر: `get_pattern("filter-panel")`. يستهدف V14-UX-005 (فلاتر متدرجة).

- أبعاد الفلاتر ≥4 → لوحة جانبية 240–280px أو درج على الهاتف؛ أقل من ذلك → شريط chips فوق النتائج (وهذا ما تريده الخطة: الأساسية ظاهرة والمتقدمة خلف كشف).
- تطبيق فوري مع debounce‏ 300ms بدل زر Apply.
- حالة الفلاتر في query params ‏(رجوع/مشاركة يعملان).
- chips نشطة فوق النتائج دائمًا، كل chip قابل للإزالة.
- نتائج صفر بسبب فلترة → فراغ من نوع «امسح الفلاتر» (يربط بنمط 2.1).

### 2.4 جدول البيانات — نمط `data-table`
المصدر: `get_pattern("data-table")`. يستهدف صفحات `/archive`, `/work-inbox`, `/inbox`.

- ارتفاع صف مريح 52px / مدمج 40px؛ حدّة سفلية 1px بين الصفوف.
- رؤوس أعمدة لاصقة عند التمرير العمودي (`.data-table-sticky-end` موجود أفقيًا — يكمل عموديًا).
- hover صف: تلوين خفيف 100ms + كشف أفعال الصف — لا أزرار في كل خلية.
- تحديد جماعي بشريط يظهر فوق الرأس عند أول تحديد.
- فراغ الجدول يمتد على كل الأعمدة (variant «Table empty»).
- RTL: كل المقاسات بخصائص منطقية (`inline-size`, `inset-inline-end`) — القاعدة موجودة في CSS الحالي وتُعمَّم على أي جدول جديد.

## 3. توكنز مقترحة (إضافات على `theme.css` — لا استبدال)

```css
/* سلّم الأسطح بأسلوب Linear — يكمّل anthracite الحالي */
--surface-ladder-1: var(--color-bg-secondary);      /* #181B22 */
--surface-ladder-2: var(--color-bg-tertiary);       /* #1E2128 */
--surface-ladder-3: var(--color-surface-elevated);  /* #252830 */
--hairline: var(--color-border-secondary);
--hairline-strong: var(--color-border-strong);

/* إيقاع حالة (Superhuman) */
--weight-ui-small: 550;
--leading-display: 1.15;   /* عربية تحتاج >1.0 — لا ضغط سالب على العربية */
```

> تنبيه عربي: التتبع السالب (negative letter-spacing) الذي ينص عليه نمط Runway/Linear **ممنوع على العربية** — `letter-spacing: 0` الحالي صحيح ويبقى.

## 5. بوابة قبول إضافية لكل صفحة (تُدمج في ROUTE_COVERAGE)

1. كل حالة بيانات تمر عبر `AsyncStateSurface` (loading/empty/error/success) — لا سبينرات ولا فراغات يدوية.
2. الفراغ يطابق نوعه (أول مرة / فلترة / ممنوع) برسالة وCTA صحيحين بالعربية والإنجليزية.
3. الخطأ: لا نص خام، retry يعمل، `role="alert"`.
4. الجداول: صفوف 40–52px، رؤوس لاصقة، hover ≤100ms، فراغ الجدول بعرض كامل.
5. الفلاتر: chips نشطة مرئية، حالة في URL، debounce 300ms.
6. لا letter-spacing سالب على نص عربي، وكل المقاسات خصائص منطقية.

## 6. كيف نعيد استخدام DesignMD لاحقًا

الخادم محفوظ في `config.yaml` باسم `designmd` (يتطلب إعادة تشغيل Hermes لتظهر أدواته مباشرة `mcp_designmd_*`). حتى ذلك الحين يمكن الاستدعاء اليدوي:

```bash
python "$LOCALAPPDATA/Temp/dmd_call.py" search_patterns '{"query": "..."}'
python "$LOCALAPPDATA/Temp/dmd_call.py" get_design '{"slug": "linear"}'
```

أنماط مفيدة قادمة لمواصفات تفصيلية عند تنفيذ كل مهمة: `get_block("dashboard-sidebar-*")` لهيكل الغلاف، `get_motion(slug)` لحركات 10-motion.css، و`certify_conformance` لتقييم HTML مبني مقابل نظام مرجعي بعد النشر التجريبي.
