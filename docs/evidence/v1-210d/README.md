## ما لم يتحقق ولماذا

**التحديث والتراجع الفعليان (`update`/`rollback`)** يحتاجان *وصف إصدار موقَّع*
(`release descriptor`) بصور Docker مثبّتة عبر مراجع `@sha256:` من سجل حاويات
حقيقي (`scripts/control-center/release-descriptor.mjs`) — بنية تحتية توزيع
منفصلة تمامًا عن نشر التطوير المحلي، وليست شيئًا يُختلق بأمان في هذه الجلسة.
افتعال وصف إصدار وهمي هنا كان سيكرر بالضبط خطأ الأدلة الملوَّثة الذي اكتُشف
وصُحِّح في V1-307 من هذه الجلسة نفسها — رُفض عمدًا.

**غير مُختبر أيضًا:** وضع `offline` الفعلي (اختبار حزمة offline-bundle حية)،
Windows 10 تحديدًا (الاختبار جرى على Windows 11 فقط)، وإعادة التشغيل الكامل
لهذا المضيف الحقيقي (VM أو جهاز نظيف منفصل تمامًا عن بيئة التطوير).

## الخطوات المتبقية للإغلاق

1. بناء وصف إصدار موقّع حقيقي (صور مثبّتة بـ`@sha256:` من سجل فعلي) عبر
   `scripts/control-center/release-descriptor.mjs`.
2. تشغيل `install --config=<file>` (لا `deploy --local`) لإثبات السلسلة
   الموقّعة، ثم `update` و`rollback` فعليًا عليها.
3. تكرار السيناريو على Windows 10، وعلى وضع `offline`.
4. تنظيف بعد كل تشغيل (كما جرى هنا: `docker compose down -v` + إزالة الـworktree).

## التنظيف بعد هذا التشغيل

`docker compose down -v` أزال كل الحاويات والشبكة والأحجام المعزولة
(`archive_v1210d_*`) بنجاح كامل — تحقّق `docker ps -a`/`docker volume ls` بعد
التفكيك يؤكد صفر أثر. المكدس الحي (`infra-*-1`) لم يتأثر طوال العملية.
