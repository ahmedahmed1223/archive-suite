# V1-303D — أدلة قارئ الشاشة ولوحة المفاتيح

## ما يثبته هذا المجلد

لكل مسار من المسارات اليومية الستة، ملف يحتوي:

1. **ترتيب النطق عند Tab** — كل محطة تركيز بالترتيب، بدورها وباسمها المنطوق.
   هذا حرفيًا ما ينطقه قارئ الشاشة عند التنقل بـ Tab.
2. **شجرة الوصولية لـ `#main-content`** — البنية التي يقرأها قارئ الشاشة.

المسارات: `/archive`، `/archive/[id]`، `/search`، `/uploads`،
`/settings/users`، `/system/control` — وهي نفس مجموعة
`keyboard-navigation-authenticated.authed.spec.ts`، حتى يصف الشقّان السطح نفسه.

## كيف تُولَّد

```bash
E2E_BASE_URL=http://localhost:3000 pnpm --filter @archive/next exec playwright test e2e/screen-reader-sample.authed.spec.ts --project=authenticated
```

الاختبار جزء من البوابة الحية (`pnpm verify:laravel-next:live`)، ويفشل إذا ظهر
عنصر قابل للتركيز بلا اسم منطوق — وهو العيب الذي تكشفه الجلسة البشرية فعليًا.
الملفات هنا نتاج تشغيل ناجح، تُعاد كتابتها في كل تشغيل.

## انحراف موثّق عن معيار الإغلاق الأصلي

**المعيار الأصلي:** عيّنة بشرية على NVDA أو VoiceOver.
**المعتمد بدلًا منه:** التقاط آلي لشجرة الوصولية وترتيب النطق، مع تأكيد وجود
اسم لكل محطة تركيز.

**السبب:** لا يتوفر NVDA على بيئة التطوير، وWindows Narrator لا يطابق المعيار
المحدد. الشجرة الملتقطة هي المصدر نفسه الذي يقرأ منه NVDA، فالفجوة الفعلية
ليست في *ماذا يُنطق* بل في *جودة الصياغة المنطوقة*.

**ما يبقى خارج النطاق:** الحكم البشري على طبيعية الصياغة العربية المنطوقة،
وسلوك أوضاع التصفح الخاصة بـ NVDA (browse/focus mode). يُغطّى الشق الأول جزئيًا
بتدقيق V1-306B العربي. أي جلسة NVDA لاحقة تُسجَّل هنا كإضافة، لا كإعادة فتح.
