# طابور مهام الوسائط والمشتقات

[English](media-derivatives.md) · [فهرس التوثيق](README.ar.md)

كل عملية وسائط — صورة مصغّرة أو تحويل أو تفريغ أو OCR أو تصدير مونتاج أو
توليد مشتقة — تعمل كمهمة `MediaJob` على عامل طابور Laravel. تغطي هذه الصفحة
سلوك الطابور وضغط الحمل وكيفية عمل إعادة المحاولة والإلغاء؛ راجع
[التفريغ باستخدام Whisper](whisper.ar.md) لإعدادات التفريغ نفسها.

## الطابور وضغط الحمل

تعمل المهام على طابور `default`، إلا مهام التفريغ عندما يكون جهاز Whisper في
النظام مضبوطًا على `cuda`، فتُوجَّه إلى طابور `gpu` المنفصل وعامله المخصص.
توليد المشتقات وكل عملية أخرى تستخدم `default` دائمًا — لا مسار مسرَّع بـGPU
حاليًا للصور المصغّرة أو الموجات الصوتية أو نسخ المعاينة.

لمنع نمو الطابور بلا حدود، تُرفض مهمة جديدة برمز `429 Too Many Requests` (مع
ترويسة `Retry-After: 30`) عندما يبلغ طابورها بالفعل `MEDIA_MAX_QUEUED_JOBS_PER_QUEUE`
(50 افتراضيًا) مهمة قيد الانتظار أو المعالجة. أعد المحاولة بعد المهلة
المذكورة بدل إعادة الإرسال فورًا.

| الإعداد | الأثر | الافتراضي |
| --- | --- | --- |
| `MEDIA_MAX_QUEUED_JOBS_PER_QUEUE` | عدد المهام المسموح في الطابور قبل رفض مهام جديدة | 50 |
| `MEDIA_JOB_TIMEOUT_SECONDS` | أقصى وقت لتشغيل المهمة قبل أن ينهيها عامل طابور Laravel | 900 |
| `MEDIA_PROCESS_TIMEOUT_SECONDS` | أقصى وقت لعملية `ffmpeg`/التفريغ الأساسية | 900 |
| `MEDIA_JOB_TRIES` | محاولات إعادة التشغيل التلقائية لمهمة فاشلة | 3 |
| — | التأخير قبل كل محاولة تلقائية | 30 ثانية، ثم 120، ثم 300 |
| `MEDIA_JOB_UNIQUE_FOR_SECONDS` | مدة تجاهل إرسال مكرر لمعرّف المهمة نفسه بدل معالجته مرتين | 3600 |
| `MEDIA_JOB_RETENTION_DAYS` | العمر الذي يُحذف بعده صف مهمة مكتملة أو فاشلة أو ملغاة. المهام قيد الانتظار أو المعالجة لا تُحذف أبدًا بصرف النظر عن عمرها. | 90 |

المحاولات التلقائية تفيد فقط مع الأعطال العابرة (عطل قرص مؤقت، انقطاع قصير
لخدمة OCR)؛ العطل الحتمي — ملف تالف، برنامج مفقود — يفشل بالطريقة نفسها في كل
محاولة.

## أنواع المشتقات

المشتقة واحدة من `thumbnail` أو `waveform` أو `proxy`. تُخزَّن حسب توليفة
دقيقة من السجل والمرفق ونوع المشتقة وإصدار المصدر وإعدادات التوليد: طلب
مشتقة جاهزة بالفعل أو قيد المعالجة لهذه التوليفة نفسها يعيد الموجودة بدل بدء
عمل مكرر. طلب مشتقة مجددًا بعد فشل محاولة سابقة يعيد ضبطها ويرسل مهمة جديدة
تلقائيًا — لا يوجد إجراء إعادة محاولة يدوي منفصل.

## الإلغاء وإعادة المحاولة

يمكن إلغاء أي مهمة ما زالت `queued` أو `processing`؛ لا يمكن إلغاء مهمة
`completed` أو `failed` أو ملغاة بالفعل مجددًا. الإلغاء يوقف معاملتها كعمل
جارٍ لكنه لا يحذف تاريخها. لإعادة محاولة *عمل* مهمة فاشلة، أعد إرسال العملية
نفسها (للمشتقة، اطلبها مجددًا بالمعاملات نفسها)؛ لا يعيد الطابور تلقائيًا
تشغيل الإرسال الأصلي لمهمة ملغاة أو فاشلة.

## التوجيه إلى GPU

التفريغ فقط يحترم طابور GPU، وفقط عندما يكون جهاز Whisper في النظام `cuda`
وعامل GPU (`laravel-worker-gpu`) يعمل — راجع
[التفريغ باستخدام Whisper](whisper.ar.md#التشغيل-على-gpu). إذا اختير `cuda`
من دون عامل GPU سليم، تفشل المهمة برسالة خطأ تشغيلية بدل التحول بصمت إلى
CPU. مهام الصورة المصغّرة والتحويل وOCR وتصدير المونتاج والمشتقات لا تُسرَّع
بـGPU وتعمل دائمًا على عامل CPU.
