# التثبيت للتشغيل المباشر دون حاويات (Native)

[English](native-installation.md) · [فهرس التوثيق](README.ar.md)

يوفر Archive Suite `v1.1.0` حزمًا مدعومة لنظامي Windows وLinux، وتشغّل هذه
الحزم خدمات Laravel وNext.js المعتمدة من دون Docker على جهاز الاستخدام.

## التنزيل والتحقق

نزّل حزمة منصتك ودليل قبولها وملف `SHA256SUMS` من صفحة إصدار `v1.1.0` العامة
على GitHub. تحقق من سجل البصمات قبل فك أي ملف أو تشغيله:

```powershell
Get-FileHash .\archive-suite-v1.1.0-windows-native.tar.gz -Algorithm SHA256
```

```bash
sha256sum --check SHA256SUMS
```

قارن نتيجة Windows بالسطر المطابق في `SHA256SUMS`. لا تستخدم الحزمة إذا
اختلفت البصمة أو لم تجد دليل قبول المنصة ضمن أصول الإصدار.

## المتطلبات

- Windows 10 أو 11 مع موافقة مسؤول النظام لتسجيل الخدمات، أو توزيعة Linux
  تستخدم `systemd` مع الصلاحيات النظامية المناسبة.
- موارد لا تقل عن خط الأساس الموضح في [دعم المنصات](platform-parity.ar.md).
- PostgreSQL مُدار توفره حزمة Windows، أو خادم PostgreSQL خارجي تديره الجهة
  المشغّلة ويدعم `pgvector`. Redis اختياري.
- مسار بيانات محمي وعنوان للتطبيق وبيانات اعتماد للخدمات. لا تنشر ملفات البيئة
  أو الأسرار التي ينشئها الإعداد.

## التثبيت والتحقق

فك الحزمة في مجلد جديد، ثم افتح Control Center من داخله واختر `native` والمنصة
المطابقة. شغّل فحص ما قبل التثبيت، وهو فحص للقراءة فقط، قبل السماح بالتثبيت:

```powershell
node scripts/control-center.mjs doctor
node scripts/control-center.mjs wizard
```

بعد التثبيت، شغّل `node scripts/control-center.mjs health`. تأكد من سلامة
التطبيق وAPI والعامل والمجدول وخدمة الوقت الفعلي وPostgreSQL وأي خدمة اختيارية
فعّلتها. احتفظ بحزمة الإصدار و`SHA256SUMS` حتى إنشاء النسخة الاحتياطية التالية
والتحقق منها.

## الترقية والاستعادة

أنشئ نسخة احتياطية وتحقق منها قبل التحديث. احتفظ بالحزمة السابقة حتى تجتاز
النسخة الجديدة فحوص الصحة وتجربة فعلية للبحث والرفع ومعالجة الوسائط. استخدم
Control Center للتحديث والرجوع والنسخ الاحتياطي والاستعادة وإلغاء التثبيت، حتى
يقتصر التنظيف على المسارات المسجلة في بيان التثبيت. راجع [دليل
الدعم](ops/support.ar.md) و[دليل Whisper](whisper.ar.md).

تعمل ترحيلات قاعدة البيانات تلقائيًا ضمن إجراء `update`؛ وهي تضيف جداولًا
وأعمدة فقط ولا تعيد كتابة البيانات الموجودة أو تحذفها، فلا حاجة لخطوة ترحيل
بيانات يدوية. إذا فشل فحص الصحة أو عملية فعلية بعد التحديث، استعد النسخة
الاحتياطية التي تحققت منها قبل التحديث بدل محاولة التراجع عن بنية قاعدة
البيانات يدويًا.
