# دليل التشغيل

[English](operations-runbook.md) · [دليل الإدارة](admin-guide.ar.md) ·
[خطة الاستعادة](restore-plan.ar.md)

ما يحتاجه المشغّل ليبقي الإصدار 2 يعمل: كيف يُرفع، وما الذي يُفحص كل يوم، وما
الذي يفعله عند أول إشارة عطل. الإجراءات هنا مأخوذة من الأوامر والمسارات
الموجودة فعلًا في المستودع، لا من ممارسة عامة.

## طوبولوجيا التشغيل

المسار المدعوم هو Docker. يصف `infra/docker-compose.release.yml` تسع خدمات:

| الخدمة | دورها | إن سقطت |
| --- | --- | --- |
| `postgres` | قاعدة البيانات | يتوقف كل شيء |
| `redis` | الجلسات والتخزين المؤقت والبث | تتدهور الجلسات والتحديث الحي |
| `laravel-fpm` | معالجة طلبات API | تتوقف الواجهة عن العمل |
| `laravel` | خادم التطبيق | كما أعلاه |
| `laravel-worker` | طابور الوسائط: probe وQC والمشتقات والتفريغ | يُقبل الرفع ولا تُعالج المادة أبدًا |
| `laravel-reverb` | البث الحي | تعود اللوحات إلى الاستطلاع الدوري |
| `next` | واجهة المستخدم | لا واجهة |
| `ocr` | استخراج النص من الصور والمستندات | تبقى مهام OCR في الطابور |
| `caddy` | الواجهة الأمامية وTLS | لا وصول خارجي |

**`laravel-worker` هو الخدمة التي يسهل نسيانها.** الرفع ينجح بدونها ويبدو
سليمًا: السجل يُنشأ، ولا يُنتج probe ولا QC ولا نسخة عرض أبدًا. أي أن غيابها
يظهر كبطء لا كعطل.

## فحص الصحة

- `GET /api/v1/health` — فحص عميق تستخدمه فحوص Compose.
- `GET /api/v1/system/services` — حالة ffmpeg وffprobe وwhisper وReverb وGPU
  وموصلات التخزين. تعرضها الواجهة في `/media/jobs`.
- `GET /api/v1/system/dr-probe` — جاهزية الاستعادة (للمدير فقط). انظر
  [خطة الاستعادة](restore-plan.ar.md).

## المهام المجدولة

يشغّلها `php artisan schedule:work` داخل حاوية التطبيق:

| الأمر | الوتيرة | الغرض |
| --- | --- | --- |
| `uploads:dispatch-scheduled` | كل دقيقة | إطلاق عمليات الرفع المجدولة المستحقة |
| `uploads:recover-scheduled` | كل 5 دقائق | استرجاع الرفع العالق بعد سقوط عامل |
| `tasks:check-escalations` | كل 15 دقيقة | تصعيد المهام المتأخرة |
| `metrics:capture` | كل ساعة | عيّنة القياسات التي يبني عليها تنبؤ التخزين |
| `uploads:cleanup-scheduled` | كل ساعة | تنظيف بقايا الرفع |
| `sessions:prune` و`audit:prune` و`metrics:prune` و`trash:prune` و`media:prune-jobs` | يوميًا | تقليم البيانات المنتهية |
| `audit:verify-chain` | يوميًا | التحقق من سلسلة سجل التدقيق |
| `files:verify-integrity` | يوميًا | مطابقة بصمات الملفات |
| `backup:cleanup` | يوميًا | حذف النسخ الأقدم من مدة الاحتفاظ |

**`archive:backup-run` ليس ضمن المجدول.** التنظيف مجدول والإنشاء ليس كذلك، أي
أن **النسخ الاحتياطي لا يحدث تلقائيًا**: على المشغّل جدولته بنفسه قبل الإطلاق.
هذا شرط سابق للإطلاق لا ملاحظة تشغيلية.

## الروتين اليومي

1. افتح `/status` وتحقق من أن الطوابير ليست متراكمة.
2. افتح `/media/jobs` وراجع لوحة حالة الخدمات: أي خدمة بحالة `down` أو
   `requires_setup` تعني قدرة معطّلة لا خللًا عابرًا.
3. افتح `/errors` وراجع الإخفاقات القابلة للإجراء. المهمة الفاشلة تُعاد
   معالجتها من الصفحة نفسها عندما تقبل العملية إعادة المحاولة.
4. تأكد من وجود نسخة احتياطية من آخر 24 ساعة:
   `php artisan archive:backup-list --json`.

## أوامر التشغيل

تُشغَّل داخل حاوية التطبيق (`docker compose exec laravel …`):

```
php artisan archive:backup-run --json        # نسخة احتياطية الآن
php artisan archive:backup-list --json       # النسخ المتاحة
php artisan archive:backup-verify <name>     # التحقق من سلامة نسخة
php artisan backup:dr-drill                  # تمرين استعادة يقيس RTO
php artisan dr:report                        # تقرير RPO/RTO
php artisan files:verify-integrity --json    # مطابقة بصمات الملفات
php artisan audit:verify-chain --json        # سلامة سلسلة التدقيق
php artisan archive:migrate-safe             # ترحيل مع نسخة احتياطية مسبقة
```

`archive:migrate-safe` يأخذ نسخة قبل الترحيل ويُبقي وضع الصيانة مفعّلًا ويخرج
بقيمة غير صفرية إذا فشل الترحيل — استخدمه بدل `migrate` المجرّد عند الترقية.

## أعراض شائعة

| العرض | الفحص الأول | الغالب |
| --- | --- | --- |
| الرفع ينجح ولا تظهر نسخة عرض | `docker compose ps laravel-worker` | العامل متوقف أو الطابور غير مستهلك |
| كل مشاركة أو تصدير مرفوض | `GET /api/v1/rights/{itemId}/enforcement` | لا نافذة حقوق للاستخدام المطلوب — الرفض افتراضي بالتصميم |
| لوحة حالة الخدمات فارغة أو ترفض | جلسة المستخدم وصلاحيته | الصفحة تحتاج جلسة إدارية |
| لا يظهر تفريغ في البحث | صيغة التفريغ | البحث الزمني يقرأ تتابع VTT بأسطر توقيت فقط |
| «لا تملك صلاحية» على صفحة إدارية | دور المستخدم | حدّ صلاحية لا عطل؛ إعادة المحاولة لن تغيّر النتيجة |

## بوابات ما قبل النشر

```
pnpm verify                      # العقود والأنواع والبناء والنظافة واختبارات Laravel وNext
pnpm verify:laravel-next:live    # Playwright على Laravel وNext حيَّين
pnpm release:verify              # ما سبق + المثبّتات والأمن وجاهزية وثائق الإصدار
```

القبول الحي من الإدخال إلى الاعتماد يحتاج معالج وسائط حقيقيًا:

```
MEDIA_PROCESSOR=real ARCHIVE_E2E_SPECS=e2e/v2-release-acceptance.authed.spec.ts pnpm verify:laravel-next:live
```
