# الدعم التشغيلي — مسار

[English](rc-launch-and-support.en.md) · [فهرس التوثيق](../README.ar.md)

يشرح هذا الدليل استقبال بلاغات التشغيل وإدارتها في مسار.

## النطاق

- الإصدار القانوني: Laravel + Next.js فقط.
- التثبيت المدعوم: Docker من artifact غير قابل للتغيير أو bundle offline موثّق.
- لا تُستخدم شجرة العمل أو صور محلية غير موقعة كمصدر تثبيت للمستخدمين.
- التكاملات الخارجية غير المهيأة تبقى معطلة؛ لا تُدخل مفاتيحها في تذكرة الدعم أو السجل.

## قبل فتح الدعم

1. سجّل version وcommit وimage digests وSHA-256 للـ bundle في سجل الإصدار المقيد.
2. شغّل `pnpm release:verify` على commit المرشح وسجّل النتيجة.
3. تحقق من `/api/v1/health` بعد التثبيت ومن توفر النسخ الاحتياطي وسجل التدقيق.
4. نفذ rollback rehearsal على بيئة غير إنتاجية باستخدام artifact موقّع سابق.
5. شارك هذا الدليل مع فريق التشغيل والدعم.

## استقبال البلاغات

يجب أن تتضمن كل تذكرة:

- رقم الإصدار وcommit أو digest، ونوع التثبيت (Docker أو offline).
- الوقت والمنطقة الزمنية والخطوات القابلة لإعادة الإنتاج.
- الدور المستخدم والمسار المتأثر، من دون كلمة مرور أو access token.
- رابط support bundle منزوع الأسرار أو مقتطف سجل منقح.
- أثر العمل: توقف كامل، فقد/تعرض بيانات محتمل، تعطل وظيفة، أو مشكلة واجهة.

لا تُقبل لقطات تحتوي على وثائق أرشيف حقيقية أو سلسلة اتصال أو مفاتيح. ينشئ فريق الدعم الحزمة عبر Control Center ويحفظ النسخة غير المنقحة في مخزن الأدلة المقيد فقط.

## الشدة والاستجابة

| الشدة | المعيار | الاستجابة الأولية | الإجراء |
| --- | --- | --- | --- |
| P0 | تعرض بيانات، فقد بيانات، أو توقف الخدمة بالكامل | فوري | احتواء، منع عمليات خطرة، تفعيل rollback عند انطباق شرطه |
| P1 | وظيفة أساسية متعطلة بلا بديل آمن | خلال يوم عمل | فرز البلاغ وتحديد مالك الإصلاح |
| P2 | خلل غير حاسم مع بديل واضح | خلال 3 أيام عمل | تسجيله في ledger وتحديد المالك والموعد |

كل P0/P1 يمنع الانتقال إلى GA حتى إغلاقه بدليل إعادة اختبار. لا يحذف البلاغ؛ تسجل التصحيحات كإضافات مؤرخة إلى ledger.

## التحقق الأولي للدعم

1. تأكد من مصدر artifact وchecksum قبل أي تشخيص.
2. اقرأ health وqueue وbackup status قبل إعادة تشغيل أي خدمة.
3. اجمع support bundle منقحًا؛ لا تنسخ `.env` أو database dump إلى قناة عامة.
4. أعد إنتاج الخطأ على بيانات اصطناعية إن أمكن.
5. إذا طابق البلاغ شرط rollback المعلن، أوقف التغيير وتواصل مع Release Owner؛ لا تنفذ rollback غير مؤكد.

## الإغلاق والتسليم

يغلق البلاغ عند ربطه بإصلاح ونتيجة إعادة اختبار ومالك وتاريخ. في المراجعة اليومية يراجع الفريق أخطاء API وعمر الصفوف وصحة النسخ الاحتياطي وفشل المعالجة وتنبيهات الشهادة.

## حدود هذه الوثيقة

لا تنشر هذه الوثيقة إلى خادم ولا تحتوي أسرارًا. استخدم Control Center في إجراءات النشر والصيانة.
