# V1-502 إلى V1-504 — التشغيل التجريبي والفرز

هذا المستند هو العقد التشغيلي والقوالب المحلية للتشغيل التجريبي. لا يمثل
إثباتاً بأن بيئة تجريبية قد نُشرت أو أن مشكلة قد أُغلقت. لا تتغير حالة أي بند
في `TASKS.md` إلا بعد إرفاق الأدلة الخارجية المعرّفة هنا.

## V1-502: سجل البيئات التجريبية

يلزم سجل واحد لكل بيئة، محفوظ ضمن حزمة الأدلة المنزوعة الأسرار:

| الحقل | القيمة المطلوبة |
| --- | --- |
| pilot ID | معرّف ثابت، مثل `pilot-2026-08-01-a` |
| النظام/النمط | Windows أو Linux؛ Docker أو Native؛ online أو offline |
| clean host | `yes`/`no` مع صورة النظام وتاريخها؛ لا يقبل `no` كبينة clean-host |
| artifact source | رابط تنزيل عام أو مسار وسائط مع checksum؛ لا workspace أو registry خاص |
| الإصدار | tag وcommit وversion وdigest وprovenance والتوقيع |
| المالك والتاريخ | اسم الدور، لا أسرار أو بيانات شخصية غير لازمة |
| النتائج | onboarding لكل دور، التثبيت، التحديث/التراجع، النسخ/الاستعادة، الصحة |
| المرفقات | manifest وlogs وsupport bundle ولقطات منزوعة الأسرار |

لا يمكن احتساب `pilot` نجاحاً إلا إذا غطت السجلات 3–5 بيئات، Windows وLinux،
Docker وNative، ومساري online/offline باستخدام artifacts موقعة فقط. أي نقص
يبقى `external-required` ولا يمرر بوابة RC.

## V1-503: ورقة قياسات التشغيل

سجل القياس لكل محاولة يجب أن يحتوي baseline المعلن، نسخة أداة القياس، وقت
البدء/النهاية، مواصفات المضيف، وحالة النجاح أو الفشل:

| القياس | وحدة القياس | المصدر | النتيجة | حالة الدليل |
| --- | --- | --- | --- | --- |
| زمن التثبيت | ثانية | سجل setup | — | pending |
| onboarding لكل دور | نجاح/فشل ومدة | رحلة browser مسجلة | — | pending |
| LCP/CLS/INP وAPI | عقد الأداء | تقرير performance | — | pending |
| RPO/RTO | مدة وفقد بيانات | DR drill | — | pending |
| CPU/RAM/disk/queue | ذروة وp95 | مراقبة المضيف | — | pending |
| معدل الأخطاء | نسبة/عداد | API وworker logs | — | pending |

المقارنة تتم فقط بمثيل benchmark والبيانات المعلن عنها. لا تدمج نتائج جهاز
مطور أو محاكاة محل قياس pilot خارجي.

## V1-504: دفتر فرز Pilot

كل مشكلة مكتشفة تسجل كسطر غير قابل للحذف (تضاف ملاحظة تصحيحية بدلاً من تعديل
السجل الأصلي):

| issue ID | المصدر/الدليل | الشدة | الأثر | القرار | المالك | الموعد | الحالة |
| --- | --- | --- | --- | --- | --- | --- | --- |
| مثال: `PILOT-001` | رابط evidence | P0/P1/P2 | عربي واضح | fix/defer | الدور | YYYY-MM-DD | open |

قواعد البوابة:

- لا P0 أو P1 مفتوح عند طلب RC أو GA.
- لا يؤجل P2 إلا بقرار Product مكتوب يذكر الأثر والحل المؤقت والموعد؛ الحقول
  الفارغة تعني أن القرار غير صالح.
- الرابط إلى attempt والدليل إلزامي؛ لا تكفي عبارة «تم الاختبار».
- يراجع Product وOperations الدفتر قبل إنشاء قرار Go/No-Go، لكن ذلك لا يعادل
  توقيع الموافقة نفسه.

## حزمة pilot المنزوعة الأسرار

```text
pilot/<pilot-id>/
  environment.json          # حقول V1-502
  measurements.json         # صفوف V1-503
  triage-ledger.md          # صفوف V1-504 وقرارات التأجيل
  evidence-manifest.json    # hashes وروابط الملفات فقط
  sanitized-logs/
  support-bundle-redacted.zip
```

تحظر الحزمة كلمات المرور، tokens، مفاتيح API، connection strings، وملفات
الإنتاج الخام. تحفظ النسخة غير المنقحة فقط في نظام الأدلة المقيد المخصص، ولا
تُرفق بالمستودع.
