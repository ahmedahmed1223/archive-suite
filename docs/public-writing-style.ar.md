# أسلوب التوثيق العام

[English](public-writing-style.md) · [فهرس التوثيق](README.ar.md)

يُطبّق هذا الدليل على جميع صفحات Archive Suite المنشورة للعامة. يصف التوثيق
السلوك المدعوم في المنتج، ولا يعرض تاريخ التنفيذ الداخلي.

## الجمهور وبنية الصفحة

- ابدأ بالنتيجة التي سيحصل عليها القارئ وحدد الجمهور المقصود.
- ضع المتطلبات قبل الأوامر، وخطوات التحقق بعدها.
- خصص كل صفحة لموضوع واحد، واربطها بالمرجع المعتمد بدل نسخ محتواه.
- اكتب الأوامر والمسارات ومتغيرات البيئة ومسارات API وأسماء المنتجات بدقة.
- لا تنشر قوائم المهام أو أدلة القبول أو ملاحظات الوكلاء أو العوائق المؤقتة أو
  مراحل الإطلاق أو الأعمال التي ما زالت قيد التقييم.

## العربية والإنجليزية

لكل صفحة عامة حية نسختان متكافئتان. تحمل الإنجليزية الاسم الافتراضي بلاحقة
`.md`، وتحمل العربية اللاحقة `.ar.md`. يجب أن تغطي النسختان القدرات والمتطلبات
وتحذيرات السلامة والأوامر وخطوات التحقق نفسها، ولا يشترط أن يتساوى عدد الأسطر
أو أن تتطابق الجمل حرفيًا.

اكتب العربية الفصحى الحديثة بلغة طبيعية تناسب مستخدم المنتج. لا تنقل ترتيب
الجملة الإنجليزية، وأبقِ المعرّفات التقنية الدقيقة بالإنجليزية عندما يحتاج
القارئ إلى نسخها أو لا يوجد تعبير عربي أوضح منها.

## مصطلحات المنتج

- اكتب في أول مرة: «التشغيل المباشر دون حاويات (Native)»، ثم استخدم «التشغيل المباشر».
- استخدم «مدير كلمات المرور» و«مخزن أسرار» و«رمز وصول» و«سجل تدقيق».
- أبقِ أسماء `Docker` و`Next.js` و`Laravel` و`OpenAPI` والأوامر ومعرّفات الشيفرة كما هي.

## لغة الإصدارات

اذكر القدرات التي تثبتها الشيفرة وبيانات الإصدار فقط. لا تستخدم رقم إصدار إلا
إذا اتفقت عليه `package.json` وبيان الإصدار وبيان التثبيت والبصمات وملاحظات
الإصدار. لا مكان لمراحل العمل الهندسية السابقة في التوثيق الحي.

## قائمة المراجعة

- يعمل رابطا اللغتين ويشير كل منهما إلى الصفحة المقابلة.
- تعمل الروابط النسبية وروابط العناوين الداخلية.
- تطابق الأوامر سكربتات الجذر ومسارات التشغيل المدعومة.
- تتضمن العمليات المتلفة تنبيهًا للنسخ الاحتياطي والاستعادة.
- لا تظهر خطة داخلية أو مهمة غير مكتملة أو قيمة مؤقتة أو مرحلة قديمة.
- تبدو العربية طبيعية عند قراءتها بصوت مسموع، وتستخدم مصطلحات المنتج باتساق.
