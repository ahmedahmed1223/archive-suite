# خطة الاستعادة

[English](restore-plan.md) · [دليل التشغيل](operations-runbook.ar.md)

ما الذي تحميه النسخة الاحتياطية، وكيف تُستعاد، وكيف يُقاس ما نخسره فعلًا. كل
رقم هنا يقرأه النظام من حالته، ولا يُفترض.

## ما تحتويه النسخة

`php artisan archive:backup-run` يكتب `backup-<طابع زمني>.json.gz` ومعه ملف
بصمة `.sha256` مجاور. النسخة **قائمة بذاتها**: صفوف قاعدة البيانات **ومحتوى
الملفات** معًا، تُبثّ من القرص ملفًا ملفًا فلا يقيم في الذاكرة إلا جزء واحد
مهما كبر الأرشيف. وتُشفَّر النسخة عند تفعيل التشفير، وتبقى قابلة للبث والتحقق.

الأثر العملي: الاستعادة من نسخة واحدة تُرجع البيانات **والمواد**. لا حاجة إلى
نسخة تخزين منفصلة للوسائط لإتمام الاستعادة.

## ما الذي يمنع استعادة فاسدة

قبل أن تُمسّ أي بيانات حية:

1. **بوابة الأرشيف كاملًا.** إن وُجد ملف `.sha256` ولم يطابق، تتوقف الاستعادة
   ولا تُلمس البيانات الحية. بصمة موجودة لا تطابق تعني تلفًا أو عبثًا بعد
   الإنشاء، وهي دائمًا سبب إحباط.
2. **بوابة لكل ملف.** يُتحقق من بصمة كل ملف قبل كتابته.
3. **النسخ القديمة.** الأرشيفات السابقة لإضافة ملف البصمة تُستعاد اعتمادًا على
   التحقق البنيوي، وتُعلَّم «غير موثقة» بدل رفضها — رفضها كان سيُعطّل كل
   استعادة تاريخية.

كتابة قاعدة البيانات تجري داخل معاملة مع لقطة سابقة للاستعادة. أما كتابة
الملفات فخارج المعاملة بطبيعتها، فنظام الملفات لا يتراجع.

## الإجراء

```
# 1. ما المتاح، وأيّها أحدث
php artisan archive:backup-list --json

# 2. تحقق قبل أي قرار
php artisan archive:backup-verify backup-2026-09-16T03-00-00-000000.json.gz

# 3. عاين ما ستُرجعه (المخازن وعدد السجلات) دون تطبيق
#    POST /api/v1/system/backups/preview  {"name": "..."}

# 4. استعد — إجراء مدمّر، و--force شرط صريح
php artisan archive:backup-restore backup-2026-09-16T03-00-00-000000.json.gz --force

# 5. أثبت النتيجة
php artisan files:verify-integrity --json
php artisan audit:verify-chain --json
```

الاستعادة متاحة كذلك عبر `POST /api/v1/system/backups/restore` بصلاحية مدير،
وتُسجَّل نتيجتها — نجاحًا أو فشلًا — إشعارًا للمستخدم الذي نفّذها.

## قياس RPO وRTO

- **RPO** يُقاس مباشرة: عمر أحدث نسخة ناجحة. أي «لو فقدنا قاعدة البيانات
  الآن، فهذا أقصى ما نخسره». لا نسخة بعد تعني تعرّضًا **غير محدود** لا صفرًا.
- **RTO** يأتي من زمن آخر تمرين استعادة حقيقي (`backup:dr-drill`). وقبل أول
  تمرين يُعلَن صراحةً «لم يُقَس بعد» بدل رقم مُختلق.

```
php artisan dr:report        # RPO وRTO ومصدر كلٍّ منهما
php artisan backup:dr-drill  # تمرين استعادة يقيس RTO فعليًا
```

`GET /api/v1/system/dr-probe` (للمدير) يعيد: `lastBackupAt` و`lastBackupName`
و`lastRestoreTestAt` و`lastRestoreTestOk` و`rpoHours`.

## شروط لا بد منها قبل الإطلاق

1. **جدولة `archive:backup-run`.** المجدول يحتوي `backup:cleanup` اليومي ولا
   يحتوي الإنشاء: التنظيف يعمل والنسخ لا. بلا جدولة صريحة يبقى RPO غير محدود
   إلى الأبد.
2. **تشغيل `backup:dr-drill` مرة واحدة على الأقل.** قبلها لا قيمة لـRTO،
   ولا دليل على أن الاستعادة تعمل على هذه البيئة.
3. **تخزين نسخة خارج الجهاز.** النسخ تُكتب على القرص نفسه الذي تحميه؛ فقدان
   الجهاز يفقدها معه.
4. **تأكيد `dr-probe` أن `lastRestoreTestOk` صحيح** وأن `rpoHours` ضمن ما
   يقبله المالك.

## ماذا لو فشلت الاستعادة

- **فشل بوابة البصمة:** البيانات الحية لم تُمسّ. جرّب النسخة الأسبق بعد
  `archive:backup-verify`.
- **فشل في منتصف كتابة الملفات:** قاعدة البيانات مستعادة والملفات جزئيًا.
  `files:verify-integrity --json` يسمّي الملفات الناقصة أو غير المطابقة، ثم
  تُعاد الاستعادة من النسخة نفسها؛ الكتابة idempotent بحسب المسار.
- **أرشيف بلا ملف بصمة:** يُستعاد ويُسجَّل تحذير «سلامة غير موثقة». عامله
  كاستعادة تحتاج تحققًا بعديًا لا كاستعادة موثوقة.
