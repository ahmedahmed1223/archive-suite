# Archive Suite v1.1.0 Public Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish-ready automation and documentation for the complete Archive Suite `v1.1.0` General Availability release across Docker, Windows Native, Linux Native, and supported Whisper transcription paths.

**Architecture:** Keep the existing tag-driven GitHub Release as the single publication entry point, but split build and acceptance work into gated platform jobs that upload immutable intermediate artifacts to one final publication job. Extend the repository readiness verifier so claims about Native and Whisper support cannot drift from workflow assets, acceptance evidence, or bilingual documentation.

**Tech Stack:** GitHub Actions, Node.js 26.5.0, pnpm 11.9.0, Next.js 16/React 19, Laravel/PHP 8.5, Docker Buildx, Cosign, Trivy, PowerShell, Bash, `whisper-ctranslate2`.

## Global Constraints

- Canonical product changes stay in `archive-next/`, `archive-laravel/`, `infra/`, `scripts/`, and `docs/`; legacy packages receive no new work.
- Product version is `1.1.0`; tag and release title are `v1.1.0`.
- Windows Native and Linux Native are supported and must ship as verified release assets.
- Whisper uses `whisper-ctranslate2`; CPU is the portable baseline and GPU requires the documented acceptance prerequisites.
- Public API v1 remains backward compatible.
- Arabic and English public documentation must remain semantically aligned.
- No tag, remote push, GitHub Release, or package publication occurs until all local gates pass and the user explicitly approves publication.
