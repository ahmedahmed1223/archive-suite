# Archive Suite 1.5 Operational and NLE Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the four connected 1.5 workflows—daily work, intake and
organization, search, and a durable advanced NLE studio—without modifying the
original media source.

**Architecture:** Laravel owns validated revisioned montage data, authorization,
render manifests, and queue execution. Next.js owns an accessible editor state
machine and the operational interfaces. OpenAPI is updated before either
runtime so the generated client remains the shared contract.

**Tech Stack:** Next.js 16, React 19, TypeScript, Vitest, Playwright, Laravel,
PHPUnit, Laravel queues, Reverb, FFmpeg, Docker, OpenAPI.

**Spec:** `docs/superpowers/specs/2026-08-26-v1.5.0-operational-nle-expansion-design.md`

## Global Constraints

- Implement product behavior only in `archive-next/` and `archive-laravel/`.
- Update `docs/api/archive-contract.openapi.json`, Laravel, generated client
  bindings, and contract checks together for every public API change.
- Preserve original media: project edits persist validated instructions and
  source version tokens, never in-place media mutations.
- Build FFmpeg arguments from server-side allowlists; never execute client
  paths, filter graphs, codecs, or shell fragments directly.
- Scope workspace state and personal context by authenticated user; when
  context recording is disabled, do not read or write record, clip, project,
  or search content to browser persistence.
- Support Arabic RTL and English LTR, keyboard alternatives to drag-and-drop,
  `prefers-reduced-motion`, 320px width, and 200% zoom.
- Use `pnpm` from the repository root. Keep Docker as a verified canonical
  output. Do not change `archive-app/` or `archive-server/`.
- Each task starts red, turns green, runs its focused checks, and lands in its
  own commit.

```php
public function saveRevision(MontageProject $project, array $payload, int $expectedRevision, User $actor): MontageProjectRevision
{
    return DB::transaction(function () use ($project, $payload, $expectedRevision, $actor) {
        $project->refresh();
        if ($project->revision !== $expectedRevision) throw new MontageRevisionConflict($project);
        $this->validator->assertValid($payload);
        return $this->createNextRevision($project, $payload, $actor);
    });
}
```
