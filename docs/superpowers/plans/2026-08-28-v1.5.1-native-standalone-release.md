# v1.5.1 Native Standalone Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish complete, verifiable Windows and Linux Native Standalone release assets with safe installation and lifecycle management.

**Architecture:** Extend the existing platform bundle assemblers and Control Center instead of adding a second installer. A shared release-metadata module creates the in-bundle `RELEASE.json` and checksum inventory; platform launchers validate that inventory and route lifecycle commands into the Native Control Center path. The release workflow archives, attests, and uploads both platform assets plus operator documentation.

**Tech Stack:** Node.js ESM, PowerShell, POSIX shell, GitHub Actions, existing Control Center Native runtime adapters, Node test runner.

**Spec:** `docs/superpowers/specs/2026-08-28-v1.5.1-native-standalone-release-design.md`

## Global Constraints

- Native Standalone supports Windows x64 and Linux x64 with systemd; Docker remains a supported parallel path.
- The bundle contains managed PostgreSQL with `pgvector` and Redis; it must not silently fall back to unverified external data services.
- Every mutable operation is manifest-scoped and preserves user data by default.
- Release assets and the reconstructed offline Docker archive must be verified with SHA256 before installation or extraction.
- Arabic copy must be natural Modern Standard Arabic and have matching English documentation.
