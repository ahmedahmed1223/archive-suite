# تصميم تجربة التخزين التشغيلي متعدد المزودين

**الحالة:** معتمد مبدئيًا لتنفيذ دفعة Dropbox الموسعة.

## الهدف

إكمال تجربة التخزين داخل Archive Suite دون تعريض الأسرار أو البيانات للخطر: اختيار أي مخزن مهيأ (محلي، S3، Dropbox، أو مزود لاحق)، استعراض ملفاته، ونقل/مزامنة ملفات بين أكثر من مخزن في الوقت نفسه مع مراقبة وإلغاء واستئناف وتعامل صريح مع التعارضات والـchecksum.

## القرار

- يعرض Laravel واجهة gateway موحدة لتصفح المجلدات ونقل الملفات وحالة التشغيل؛ لا يتصل Next.js بأي مزود تخزين مباشرة.
- كل مخزن يملك هوية ثابتة، نوعًا، اسمًا عربيًا معروضًا، وحزمة capabilities (`browse`, `read`, `write`, `delete`, `copy`, `resume`). لا يظهر إجراء لا يدعمه المخزن المحدد.
- مستعرض المجلدات يتنقل مستوى واحدًا في كل طلب، ولا يحمل شجرة كاملة أو ينفذ بحثًا غير محدود؛ يبدأ المستخدم باختيار المخزن ثم المجلد.
- لكل عملية نقل أو مزامنة سجل دائم يتضمن المخزن المصدر والوجهة والحالة والتقدم والقابلية للإلغاء وموضع الاستئناف؛ لا يخزن token أو مسار محلي حساس في استجابة الواجهة أو سجل التدقيق.
- تقارن الملفات بالـchecksum قبل الاستبدال. التعارض يتطلب سياسة صريحة: تخطٍ، إنشاء نسخة جديدة، أو تحديث بعد تأكيد المستخدم.
- تتعامل gateway مع 429/5xx بإعادة محاولة محدودة؛ تعرض الواجهة وقت الانتظار والـquota بصياغة عربية.
- وضع mock يختبر تدفق الواجهة ببيانات مصطنعة ولا يمكن أن يعلن اتصال Dropbox حيًا.

## قدرات إدارة الملفات

تُفصل إدارة الكائنات المخزنة عن حذف سجل الأرشيف: حذف سجل يبقى ضمن السلة الحالية، بينما حذف ملف من مخزن يتطلب تأكيدًا صريحًا وسجل تدقيق ولا يزيل مرجعًا مرتبطًا بسجل حي بلا سياسة معلنة.

- **التصفح والاسترجاع:** اختيار مخزن، breadcrumb، فرز وتصفية وبحث داخل المجلد، معاينة آمنة وتنزيل متدفق وفق صلاحية المستخدم.
- **الإنشاء والنقل:** رفع مجزأ قابل للاستئناف، إنشاء مجلد، نسخ أو نقل داخل المخزن أو بين مخزنين، وإعادة تسمية مع التحقق من الاسم والمسار.
- **السلامة:** checksum قبل وبعد النقل، سياسة تعارض (`skip` أو `copy` أو `replace` بعد تأكيد)، قفل العملية، وإلغاء/استئناف idempotent.
- **الحذف والاستعادة:** حذف قابل للاستعادة عندما يدعمه المزود، أو تحذير صريح عند الحذف غير القابل للتراجع؛ لا يعلن النجاح قبل تأكيد المزود.
- **العمليات الجماعية:** قائمة أهداف صريحة ومعاينة للتأثير قبل النسخ/النقل/الحذف، ونتيجة مستقلة لكل ملف دون إخفاء الفشل الجزئي.
- **الحوكمة:** صلاحيات `browse/read/write/delete` مستقلة، سجل تدقيق عربي منقح، وقيود حجم/نوع/معدل قابلة للعرض.

## الواجهات

1. `GET /system/storages` يعيد المخازن المهيأة وقدراتها وحالتها دون أسرار.
2. `GET /system/storages/{store}/folders?path=` يعيد المسار الحالي والمجلد الأب والمجلدات الفرعية المسموح بها فقط.
3. `POST /system/storage-transfers` ينشئ نقلًا ضمن مخزن أو بين مخزنين، بمعرف قابل للاستئناف وسياسة تعارض.
4. `GET /system/storage-transfers/{id}` يعيد حالة آمنة: تقدم، bytes، محاولة، رسالة عربية، ووقت إعادة المحاولة عند وجوده.
5. `POST /system/storage-transfers/{id}/cancel` يطلب الإلغاء بشكل idempotent؛ التنفيذ يوقف العمل بين الأجزاء ولا يعلن نجاحًا زائفًا.
6. يبقى مسار Dropbox الحالي compatible ويُنفذ عبر adapter Dropbox تحت طبقة التخزين الموحدة أثناء الترحيل.
7. سجل التدقيق يذكر الفعل والنتيجة والسياسة والمعرفات الآمنة فقط.
8. `POST /system/storage-operations/preview` يعيد تأثير العملية الجماعية دون كتابة، و`POST /system/storage-operations` ينفذها برمز معاينة موقع وقصير العمر.

## معايير الإغلاق

تثبت اختبارات Laravel اختيار المخزن والقدرات وحدود المسارات والنقل بين مخزنين والتعارض والـchecksum والإلغاء/الاستئناف وredaction وretry. تثبت Playwright mock اختيار المخزن والمستعرض والحالة والإلغاء. يبقى V1-X01 مفتوحًا حتى اعتماد حي ببيانات Dropbox/S3 حقيقية وwebhook عام؛ يبدأ هذا الفحص فقط عند توفير الاعتمادات بموافقتك.
