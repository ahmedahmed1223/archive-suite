# تصميم تجربة Dropbox التشغيلية

**الحالة:** معتمد مبدئيًا لتنفيذ دفعة Dropbox الموسعة.

## الهدف

إكمال تجربة Dropbox داخل Archive Suite دون تعريض الأسرار أو البيانات للخطر: اختيار مجلد بصري، مزامنة قابلة للمراقبة والإلغاء والاستئناف، تعامل صريح مع التعارضات والتحقق بالـchecksum، وسجل تدقيق عربي منقح.

## القرار

- يعرض Laravel واجهة gateway واحدة لتصفح المجلدات ونقل الملفات وحالة التشغيل؛ لا يتصل Next.js بـDropbox مباشرة.
- مستعرض المجلدات يتنقل مستوى واحدًا في كل طلب، ولا يحمل شجرة كاملة أو ينفذ بحثًا غير محدود.
- لكل عملية نقل أو مزامنة سجل دائم يتضمن الحالة والتقدم والقابلية للإلغاء وموضع الاستئناف؛ لا يخزن token أو مسار محلي حساس في استجابة الواجهة أو سجل التدقيق.
- تقارن الملفات بالـchecksum قبل الاستبدال. التعارض يتطلب سياسة صريحة: تخطٍ، إنشاء نسخة جديدة، أو تحديث بعد تأكيد المستخدم.
- تتعامل gateway مع 429/5xx بإعادة محاولة محدودة؛ تعرض الواجهة وقت الانتظار والـquota بصياغة عربية.
- وضع mock يختبر تدفق الواجهة ببيانات مصطنعة ولا يمكن أن يعلن اتصال Dropbox حيًا.

## الواجهات

1. `GET /system/dropbox/folders?path=` يعيد المسار الحالي والمجلد الأب والمجلدات الفرعية المسموح بها فقط.
2. `POST /system/dropbox/transfers` ينشئ نقلًا بمعرف قابل للاستئناف وسياسة تعارض.
3. `GET /system/dropbox/transfers/{id}` يعيد حالة آمنة: تقدم، bytes، محاولة، رسالة عربية، ووقت إعادة المحاولة عند وجوده.
4. `POST /system/dropbox/transfers/{id}/cancel` يطلب الإلغاء بشكل idempotent؛ التنفيذ يوقف العمل بين الأجزاء ولا يعلن نجاحًا زائفًا.
5. سجل التدقيق يذكر الفعل والنتيجة والسياسة والمعرفات الآمنة فقط.

## معايير الإغلاق

تثبت اختبارات Laravel حدود المسارات، التعارض، checksum، إلغاء/استئناف، redaction، وretry. تثبت Playwright mock المستعرض والحالة والإلغاء. يبقى V1-X01 مفتوحًا حتى اعتماد حي ببيانات Dropbox حقيقية وwebhook عام.
