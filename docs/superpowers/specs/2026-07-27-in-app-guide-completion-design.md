# إكمال دليل المستخدم داخل التطبيق

## القرار

يعتمد الإصدار الأول دليلًا مدمجًا وخفيفًا في `/help` بدل نظام توثيق خارجي. يبقى
Markdown مصدر المحتوى القابل للصيانة، ويُعرض للمستخدم فقط ما يناسب دوره.

## البنية المعتمدة

- `archive-next/content/guide/*.md`: فصل مستقل لكل رحلة أو دور.
- `archive-next/lib/guide-content.ts`: فهرس الفصول، جمهورها، والصفحة المرتبطة.
- `archive-next/components/GuideBrowser.tsx`: بحث محلي، تصفية حسب الدور، وقراءة
  الفصل داخل صفحة المساعدة.
- `archive-next/components/AppHeader.tsx`: رابط سياقي «كيف تعمل هذه الصفحة؟»
  إلى الفصل المطابق.

## السلوك

يفتح الرابط السياقي `/help?chapter=<id>` ويختار الفصل إن كان متاحًا لدور المستخدم.
البحث محلي في العنوان والمحتوى ولا يرسل نص الدليل أو استعلام المستخدم إلى API.
إذا لم توجد نتيجة مناسبة، تظهر حالة عربية واضحة. لا تُعرض فصول المدير للمحرر أو
المستعرض.

## النطاق والمخاطر

التنفيذ الحالي يحقق البحث، الفصول بحسب الدور، مصدر Markdown، والربط السياقي. لا
تدخل لقطات شاشة ثابتة في هذه الدفعة لأنها تتقادم مع الواجهة وتحتاج مسار إنتاج
أصول ومراجعة بصرية منفصلًا. معيار الإغلاق هو تغطية الرحلات الأساسية للمستعرض
والمحرر والمدير، مع اختبار التصفية والرابط السياقي.

## التحقق

تُضاف أو تُراجع اختبارات `GuideBrowser` ومحتوى الفهرس، ثم تُشغّل بوابة `pnpm
verify` مرة واحدة بعد اكتمال الدفعة.
