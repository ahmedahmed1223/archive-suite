# إكمال مهام CloudMediaDB في Archive Suite

## الهدف

إغلاق بنود `AS-01` إلى `AS-18` في المسار القانوني `archive-laravel` و`archive-next`
فقط. لا يُغلق بند لمجرد وجود صفحة أو endpoint؛ يلزم سلوك مثبت باختبار ملائم، وعقد
API عند وجود واجهة عامة، وواجهة تشغيلية عندما ينص البند عليها.

## النهج

1. تدقيق الكود والاختبارات الحالية لكل بند وتحديد الدليل المفقود بدقة.
2. كتابة اختبار فاشل أولاً لكل فجوة وظيفية، ثم أقل تغيير يحقق السلوك.
3. تحديث OpenAPI والعميل والواجهة معاً لكل تغيير عام.
4. تحديث `TASKS.md` و`ChangeLog.md` بعد نجاح التحقق فقط، ثم commit مستقل باسم
   البند (`AS-xx`).

## حدود التنفيذ

| الدفعة | البنود | دليل الإغلاق |
|---|---|---|
| النواة والحوكمة | AS-01..AS-05 | سجلات وبيانات وصفية وتصنيفات وقاموس وصلاحيات ودورة حياة، مع اختبارات Laravel/Next المتأثرة |
| الإدخال والبحث | AS-06..AS-09 | رفع واستيراد وبحث وتفاصيل/تعاون وخدمات AI مع مراجعة بشرية |
| الإنتاج والمشاركة | AS-10..AS-13 | مجموعات ومشاريع وكانبان ومقاطع/تصدير NLE وروابط مشاركة مقيدة |
| الاستكشاف والتشغيل | AS-14..AS-18 | رسم العلاقات والخريطة/الزمن والتقارير والنسخ الاحتياطي وضوابط السحابة |

## القرارات

- القاموس يبقى موحداً؛ تفضيلات القسم ترتب النتائج ولا تنشئ قاموساً منعزلاً.
- لا تُخزّن مفاتيح السحابة في الواجهة أو سجل التدقيق، وكل endpoint محمي
  بالمصادقة والصلاحية المناسبة.
- خدمات AI تعيد نتائج اقتراحية/مراجعة فقط؛ لا تعتمد أو تنشر أو تعدل وصف مادة
  تلقائياً.
- اختبار اتصال مزود سحابي حي ليس شرطاً لإغلاق الضوابط المحلية، لكنه يبقى بند
  قدرة خارجية موثقاً منفصلاً.

## التحقق

لكل بند: اختبار مركز يثبت السلوك، فحص العقد إن تغير، فحص أنواع Next.js، وبناء
الواجهة عند تغييرها. تظل الاختبارات الحية أو الخارجية دليلاً إضافياً ولا تحل
محل الاختبارات القابلة لإعادة التشغيل.
