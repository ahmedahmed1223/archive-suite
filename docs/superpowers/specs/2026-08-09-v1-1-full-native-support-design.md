# تصميم الدعم الكامل للتشغيل الأصلي في الإصدار 1.1

## الهدف

إصدار `v1.1.0` بحزمتين أصليتين قابلتين للتثبيت والتحديث والاسترجاع والإزالة
على Windows وLinux من دون Docker على جهاز التشغيل. يدير `Native Setup` خدمات
التطبيق وخدمات البيانات، ويتيح استخدام خدمات بيانات خارجية للمؤسسات التي تديرها
مركزيًا.

## قرار خدمات البيانات

يكون الخيار الافتراضي في التثبيت الأصلي هو `managed`:

- Windows: PostgreSQL 18 مع امتداد `pgvector`، وMemurai بوصفه مزود Windows
  الأصلي المتوافق مع Redis، وpgAdmin كأداة إدارة اختيارية.
- Linux: PostgreSQL 18 مع `pgvector` وRedis 8 من المستودعات الرسمية المدعومة
  للتوزيعة. لا يُثبّت pgAdmin على الخوادم تلقائيًا، ويمكن طلبه صراحة عندما تتوفر
  حزمة رسمية للتوزيعة.
- يبقى الخيار `external` مدعومًا لـPostgreSQL وRedis، وتتحقق منه المجسات قبل
  إنشاء أي خدمة للتطبيق.

لا تُعاد تسمية Memurai إلى Redis داخل السجلات أو التوثيق. تعرض الواجهة أنه
«خدمة متوافقة مع Redis» وتعرض شرط الترخيص قبل التثبيت. لا تُضمّن نسخة Memurai
تجارية في أصول الإصدار ما لم يسمح ترخيص إعادة التوزيع بذلك؛ في الوضع المتصل
يستخدم Setup المثبّت الرسمي، وفي الوضع غير المتصل يطلب حزمة مرخصة يتحقق من
توقيعها وchecksum الخاص بها.

## الحسابات والأسرار الافتراضية

ينشئ Setup أسماء مستقرة ليسهل التشغيل، من دون كلمات مرور ثابتة:

- قاعدة البيانات: `archive`.
- مالك قاعدة البيانات: `archive_owner`.
- حساب التطبيق محدود الصلاحيات: `archive_app`.
- حساب Memurai/Redis: `archive_app` عندما يدعم المزود ACL.
- مستخدم خدمات Linux: `archive` غير تفاعلي.
- خدمات Windows: حساب افتراضي مستقل من نوع `NT SERVICE\\<service-id>`.

يولّد Setup كلمات مرور عشوائية مشفّرة آمنًا بطول لا يقل عن 32 بايت، إضافة إلى
`APP_KEY`. لا يطبع القيم في السجل أو JSON أو حزمة الدعم. يحفظها في مخزن أسرار
محلي مملوك للتثبيت: ACL محصور في Administrators وحسابات الخدمات على Windows،
وصلاحية `0600` وملكية `root:archive` على Linux. يعرض Setup مسار الاسترداد فقط،
ويدعم تدوير الأسرار بعملية مستقلة قابلة للاسترجاع.

## دورة التثبيت

يمدَّد مخطط إعداد Native ليحمل `dataServices.postgres.kind` و
`dataServices.redis.kind` بقيمتي `managed` أو `external`، وخيار `pgAdmin`.
تكون الخطوات قابلة للاستئناف ويُسجّل تقدمها في installation manifest:

1. التحقق من النظام والصلاحيات والمساحة والتوقيعات.
2. توليد الأسرار وحمايتها.
3. تثبيت PostgreSQL و`pgvector` وإنشاء القاعدة والأدوار، أو فحص endpoint خارجي.
4. تثبيت Memurai/Redis وضبط loopback وكلمة المرور والحفظ، أو فحص endpoint خارجي.
5. تثبيت pgAdmin عند طلبه.
6. كتابة إعدادات Laravel وCaddy وPHP-FPM/Windows FastCGI.
7. تسجيل خدمات التطبيق وتشغيلها.
8. تنفيذ migrations وفحص الصحة واختبار queue/cache وWebSocket والأدوار.

عند الفشل يتوقف Setup في الخطوة نفسها ولا يحذف بيانات ناجحة. يعيد `repair`
الخطوة الفاشلة بأمان. لا تعتبر العملية ناجحة حتى تنجح المجسات الوظيفية، لا مجرد
وجود العمليات.

## التحديث والاسترجاع والإزالة

- يحدّث `update` التطبيق وخدمات البيانات المملوكة ضمن نافذة صيانة: فحص مسبق،
  نسخة احتياطية، تثبيت الإصدار بجوار القديم، migrations آمنة، تبديل، ثم فحص.
- يستعيد `rollback` الإصدار السابق وإعداداته عند فشل التبديل، مع الحفاظ على
  قاعدة البيانات عندما تمنع migrations الاسترجاع غير الآمن.
- يزيل `uninstall` الخدمات والملفات التي يملكها manifest فقط. يحتفظ ببيانات
  PostgreSQL وRedis افتراضيًا، ولا يحذفها إلا بتأكيد مستقل وصريح بعد إنشاء نسخة
  احتياطية.
- لا يزيل Setup تثبيت PostgreSQL أو Memurai/Redis الموجود قبل Archive Suite؛
  يسجل الملكية عند الإنشاء ويفرق بين `managed-owned` و`managed-shared`.

## حزم الإصدار وسلسلة التوريد

ينشئ workflow الإصدار أصولًا مستقلة ومثبتة الإصدار:

- `archive-suite-v1.1.0-windows-x64.zip`
- `archive-suite-v1.1.0-linux-x64.tar.gz`
- SBOM و`SHA256SUMS` وتوقيع Cosign منفصل لكل أصل.
- قائمة بالمكونات الخارجية وتراخيصها وروابط مصادرها الرسمية.

تتحقق الحزم من توقيع ناشر PostgreSQL/pgAdmin/Memurai على Windows ومن توقيعات
مستودعات الحزم على Linux. يمنع أي checksum أو توقيع غير مطابق التثبيت قبل أي
تغيير في الجهاز.

## القبول وإعلان الدعم

تشغّل بوابة `v1.1.0` المصفوفة نفسها على Windows وLinux من أصول الإصدار النهائية
الموقعة. تغطي المصفوفة: تثبيت جديد، إعادة الضبط، تشغيل الخدمات، PostgreSQL و
`pgvector`، queue/cache عبر Redis، تحديث، استرجاع، نسخة احتياطية واستعادة، إزالة
مع الاحتفاظ بالبيانات، إزالة كاملة بتأكيد، وفحص عدم بقاء خدمات أو أسرار.

يبقى `windows-native` و`linux-native` في حالة `planned` حتى تنجح المصفوفة
كاملة. بعد النجاح فقط تتحول الحالة إلى `supported`، وتُنشر ملاحظات الإصدار
العربية والإنجليزية والحزم والتواقيع ضمن GitHub Release. أي فشل يمنع نشر tag
في الفحص المحلي السابق للدفع. أما فشل المصفوفة داخل workflow بعد دفع tag فيمنع
إنشاء GitHub Release ونشر أصوله، ولا يُستبدل بدليل مصطنع أو فحص وحدات محلي.

## حدود الإصدار

- المعماريات المدعومة في `v1.1.0`: `x64` فقط.
- Windows: Windows 10 و11 مع صلاحية Administrator أثناء التثبيت.
- Linux: توزيعات x64 تستخدم `systemd` ومدير حزم مدعومًا صراحة في عقد المنصة.
- اتصال الإنترنت مطلوب للوضع `online`. يتطلب الوضع `offline` جميع الحزم
  المرخصة والموقعة مسبقًا.
- لا ينفذ Setup إعادة تشغيل للنظام تلقائيًا. إذا تطلب مكوّن خارجي إعادة تشغيل،
  يتوقف قبل التثبيت ويعرض الإجراء المطلوب بدل فرضه.
