# تصميم إصدار v1.5.1: Native Standalone والمُثبّت الرسمي

## الهدف

يوفر `v1.5.1` أصول إصدار رسمية مستقلة لنظامي Windows وLinux تسمح بتثبيت
Archive Suite وتشغيله وإدارته محليًا دون Docker أو خدمات بيانات خارجية.
تتضمن كل حزمة التطبيق ووقت التشغيل وخدمات البيانات المطلوبة، ومُثبّتًا
متوافقًا مع المنصة، وأداة إدارة، وبيانات الإصدار والتوثيق اللازمة للتشغيل
والصيانة الآمنة.

## النطاق

يشمل الإصدار ثلاثة مسارات متكاملة:

1. حزمة Native Standalone كاملة لكل من Windows وLinux، تضم Laravel وNext.js
   وPostgreSQL مع `pgvector` وRedis والملفات والخدمات اللازمة لتشغيل ملف
   التشغيل الأساسي.
2. مُثبّت ومُدير نظام مبنيان فوق Control Center القائم، مع واجهات مناسبة
   للمنصة بدل منطق تثبيت مكرر.
3. أصول GitHub Release وتوثيق عربي وإنجليزي يشرحان التنزيل والتحقق والتثبيت
   والإدارة والتحديث والاستعادة، بما في ذلك تجميع حزمة Docker دون اتصال
   المقسمة إلى أجزاء.

لا يشمل هذا الإصدار واجهة رسومية جديدة أو استبدال مسار Docker. يبقى Docker
مسارًا رسميًا ومدعومًا بالتوازي مع Native Standalone.

## الأصول المنشورة

تنشر صفحة إصدار `v1.5.1` الأصول الآتية:

| الأصل | الغرض |
| --- | --- |
| `archive-suite-v1.5.1-windows-native.tar.gz` | حزمة Native Standalone لنظام Windows x64. |
| `archive-suite-v1.5.1-linux-native.tar.gz` | حزمة Native Standalone لنظام Linux x64 مع systemd. |
| `SHA256SUMS` | بصمات كل أصول الإصدار. |
| `RELEASE.json` | الإصدار، وقت البناء UTC، المنصة، المعمارية، بصمة الأصل، ورابط ملاحظات الإصدار. |
| `OFFLINE-BUNDLE-README.txt` و`OFFLINE-BUNDLE-SHA256` | تعليمات وبصمة تجميع حزمة Docker دون اتصال المقسمة. |
| أدلة القبول الخاصة بكل منصة | دليل اجتياز تثبيت نظيف وفحص الصحة. |

كل حزمة Native تضم أيضًا نسخة من `RELEASE.json` و`SHA256SUMS` وملف
`CHANGELOG.md` ودليل التثبيت العربي والإنجليزي، حتى تظل معلومات الإصدار
متاحة بعد نقل الحزمة إلى جهاز معزول.

## بنية حزمة Native

تحتوي الحزمة المستخرجة على بنية ثابتة:

```text
ArchiveSuite/
  install.ps1 | install.sh
  manage.ps1  | manage.sh
  RELEASE.json
  SHA256SUMS
  CHANGELOG.md
  README.ar.md
  README.md
  runtime/
  services/
  data/
  scripts/
```

ملفات `install.*` هي نقطة التثبيت الوحيدة. تتحقق من البصمات قبل نسخ الملفات
أو تسجيل الخدمات، ثم تستدعي Control Center بالوضع `native`. ملفات `manage.*`
هي واجهة مستقرة لأداة الإدارة ولا تحتوي أسرارًا أو منطق تشغيل منفصلًا.

## واجهة المُثبّت والإدارة

تدعم الحزمتان الأوامر التالية، بنفس الأسماء والسلوك حيثما أمكن:

```text
install [--yes]
doctor
status
start
stop
restart
logs
health
update
backup
restore
uninstall
```

يتطلب `restore` و`uninstall --delete-data` تأكيدًا صريحًا. لا تحذف عملية
`uninstall` البيانات أو النسخ الاحتياطية افتراضيًا. تحفظ عملية التثبيت بيان
تثبيت ذريًا يحدد الخدمات والمسارات التي يملكها Archive Suite فقط؛ وتستخدمه
عمليات الإصلاح والتحديث والإزالة لمنع لمس الملفات غير المملوكة.

## تدفق التثبيت

1. ينزّل المستخدم أصل منصته و`SHA256SUMS` من صفحة الإصدار ويتحقق من البصمة.
2. يفك الحزمة ويشغل `install.ps1` على Windows أو `install.sh` على Linux.
3. يتحقق المُثبّت من الصلاحيات والمساحة وإصدار النظام وعدم وجود تثبيت متعارض.
4. ينسخ وقت التشغيل إلى مسار ملكية محدد، وينشئ مسارات البيانات المحمية.
5. يهيئ PostgreSQL و`pgvector` وRedis محليًا، وينشئ الأسرار وملف البيئة من
   دون عرض القيم الحساسة في السجل.
6. يسجل الخدمات: Windows Service أو systemd، ثم يشغلها وفق الاعتماديات.
7. ينفذ ترحيلات Laravel الآمنة وفحص الصحة، ثم يكتب `RELEASE.json` وبيان
   التثبيت بنتيجة العملية.

أي فشل قبل تسجيل الخدمات يترك ملفات بيانات المستخدم دون حذف. أي فشل لاحق
يسجل الخطوة الناجحة الأخيرة ويعرض أمر إصلاح آمن. لا يستأنف المُثبّت خطوة
غامضة تلقائيًا.

## التحديث والاستعادة

يقارن `update` إصدار الحزمة الجديدة ببيان التثبيت الحالي، وينشئ نسخة
احتياطية موثقة قبل الإيقاف أو الترحيل. بعد تحقق البصمة، يثبت الإصدار الجديد
ويجري ترحيلات الإضافة الآمنة، ثم يجتاز فحص الصحة. يحتفظ بالإصدار السابق
والنسخة الاحتياطية المتوافقة حتى ينجح الفحص. تعتمد `restore` على نسخة
احتياطية مطابقة للبصمة وتطلب تأكيدًا قبل استبدال البيانات.

## الأمان والخصوصية

- لا تُقبل أصول غير موجودة في `SHA256SUMS` أو لا تطابق بصمتها.
- لا تخزن الأسرار في `RELEASE.json` أو سجل التثبيت أو بيان التثبيت.
- تُطبّق صلاحيات ملفات وخدمات خاصة بـ Archive Suite فقط.
- لا تفتح منافذ عامة افتراضيًا؛ يظل التعرض الشبكي قرارًا صريحًا أثناء الإعداد.
- لا يحذف المُثبّت أو المدير مسارًا خارج قائمة `ownedPaths` المسجلة.

## توثيق المستخدم

تحدّث الأدلة العربية والإنجليزية لتوضح:

- الفرق بين Docker وNative Standalone ومتى يختار المستخدم كل مسار.
- التحقق من البصمات في Windows وLinux.
- تثبيت الحزمة وإدارة الأوامر اليومية والاستعادة وإلغاء التثبيت الآمن.
- مكان العثور على رقم الإصدار وتاريخ البناء وسجل التغييرات داخل الحزمة.
- طريقة تجميع `archive-suite-offline-v1.5.1.tar.gz.part-00` وامتداداته قبل
  فك الضغط والتحقق من `OFFLINE-BUNDLE-SHA256`.

## التحقق والقبول

يتطلب الإصدار:

- اختبار وحدة لكل واجهة حزمة ولقراءة `RELEASE.json` والتحقق من البصمات.
- اختبار قبول نظيف على Windows وLinux يثبت الحزمة ويشغّل `status` و`health`
  و`backup` و`restore` و`uninstall` دون حذف البيانات افتراضيًا.
- تحقق بوابة الإصدار من وجود أصول المنصتين وتطابق رقم الإصدار والبصمات وبيانات
  الإصدار وتوثيق المستخدم.
- نجاح `pnpm release:verify` وبوابات Native القائمة قبل إنشاء GitHub Release.
