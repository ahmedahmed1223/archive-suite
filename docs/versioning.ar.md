# سياسة الإصدارات والدعم

[English](versioning.md) · [فهرس التوثيق](README.ar.md)

تتبع Archive Suite الإصدار الدلالي `MAJOR.MINOR.PATCH`:

- قد يتضمن `MAJOR` تغييرًا غير متوافق في عقد API العام أو صيغة البيانات أو النسخ الاحتياطي.
- يضيف `MINOR` قدرات متوافقة مع الإصدارات السابقة.
- يضم `PATCH` إصلاحات متوافقة مع الإصدارات السابقة.
- تُنشر الإصدارات التجريبية تحت وسمها الدقيق، ولا تحرّك الوسم `latest`.

حقل `version` في `package.json` هو المرجع المعتمد لإصدار البرنامج. يبدأ النشر
من وسم Git مطابق للصيغة `v<version>` بعد نجاح بوابة التحقق من الإصدار.

## نافذة الدعم

| سلسلة الإصدار | الدعم |
| --- | --- |
| أحدث إصدار فرعي ضمن أحدث إصدار رئيسي | إصلاحات كاملة وتحديثات أمنية |
| الإصدار الفرعي السابق مباشرة | إصلاحات أمنية لمدة ستة أشهر بعد صدور الإصدار التالي |
| الإصدارات الأقدم | يلزم الترقية |
| الإصدارات التجريبية | لا يشملها التزام الدعم |

تبقى بنية قاعدة البيانات وصيغة النسخ الاحتياطي متوافقتين ضمن الإصدار الرئيسي
نفسه، ما لم تعرض ملاحظات الإصدار إجراء ترقية صريحًا.

## سياسة المشغل

اقرأ ملاحظات الإصدار قبل التحديث، وأنشئ نسخة احتياطية وتحقق منها، واحتفظ
بنسخة متوافقة مع الإصدار السابق حتى تنجح فحوص الصحة. نفّذ التحديث والاستعادة
من خلال Control Center.

في تثبيت Native Standalone، اقرأ رقم الإصدار ووقت البناء بتوقيت UTC من ملف
`RELEASE.json` في جذر الحزمة. يحتوي `CHANGELOG.md` على سجل التغييرات المرفق
بالحزمة، بينما تبقى ملاحظات إصدار GitHub الموقعة سجل التغييرات العام المعتمد.
